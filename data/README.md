# 세모이 자판 데이터

세모이 입력 엔진(`crates/semoe-core`)이 쓰는 자판 데이터입니다.

## 출처와 라이선스

[Sinseiki/Semo-e_keyboard](https://github.com/Sinseiki/Semo-e_keyboard)의 날개셋 설정 파일에서 변환했습니다. 원본 자판(만든이 신세기)과 마찬가지로 **CC BY-SA 4.0**을 따릅니다. 변환에 쓴 원본 커밋은 `meta.json`의 `source.commit`에 있습니다.

- `세모이 (한 번에 모아치기).xml`, `세모이 (이어치기 & 중종성 모아치기).xml`: 자판, 결합 규칙, 약어, 기호 조합, 후보
- `세모이 자판 설명/세모이 자판 약어 (가나다순).xlsx`: 약어 표를 교차 검증하는 데만 씀

## 파일

| 파일 | 종류 | 내용 |
| --- | --- | --- |
| `src/unit-names.json` | 수작업 원본 | 날개셋 낱자 이름(`G_`, `BQ`, `IYE` …) → 유니코드 첫가끝 자모 |
| `src/abbreviations-extra.json` | 수작업 원본 | 원본에 없는 추가 약어 (`ojz` → 뺨) |
| `layout.json` | 생성물 | 키(ASCII 0x21~0x7E)마다 조건부 규칙 목록, 가상 낱자(모음시프트) |
| `unit-mix.json` | 생성물 | 결합 규칙 439개 (원본 그대로, 순서 있음) |
| `abbreviations.json` | 생성물 | 약어 1,363개 + 추가 약어 |
| `compose.json` | 생성물 | 기호 연타 조합 상태기계 178개 |
| `candidates.json` | 생성물 | 후보 변환 370개 |
| `meta.json` | 생성물 | 출처, 개수, 입력 방식별 오토마타·타이머 원본 식 |

생성물은 직접 고치지 말고 다시 만드세요.

```sh
scripts/gen-data.sh           # ../Semo-e_keyboard 에서 다시 만들기
scripts/gen-data.sh --check   # 최신인지 확인만 (CI)
```

## 형식 메모

- 낱자는 첫가끝 자모입니다. 가상 낱자는 사용 영역 문자 `U+F000 + id`로 나타냅니다. 모음시프트(id 500)는 `U+F1F4`이고, 단독으로 확정되면 `ᅩ`로 보입니다.
- `layout.json`의 규칙은 위에서부터 차례로 보고, `when` 조건이 모두 맞는 첫 규칙을 씁니다. 마지막 규칙에는 조건이 없습니다.
  - `stage`: 기호 확장 단계 `T`. 0 = 평소, 100 = Shift+J 뒤 준비, 101~103 = 1~3단계
  - `caps_lock`: Caps Lock (세모이에서는 Shift Lock 역할)
  - `scroll_lock`: 원본에서 옛한글·특수기호 확장 모드
  - `flag`: 날개셋 내부 플래그 `E`·`F`
- 결합 규칙은 원본의 순서를 그대로 둡니다. 원본은 대부분 두 순서를 모두 적어 두었지만 한 방향만 적힌 규칙이 24개 있습니다. 그래서 엔진은 적힌 순서를 먼저 보고, 없으면 반대 순서를 봅니다. 두 순서의 결과가 다른 규칙도 1쌍 있습니다(종성 `ㄹ+ㅍ=ㄿ`, `ㅍ+ㄹ=ㅌ`).

## 변환기가 하는 검증

1. 두 XML의 공유 표(자판, 결합, 가상 낱자, 약어, 기호 조합, 후보)가 같은지 확인합니다.
2. 조건식을 해석하지 못하거나 낱자 이름을 대응하지 못하면 오류로 멈춥니다.
3. 대응표에서 한 벌 안에 같은 문자가 두 번 나오면 안 되고, 문자는 그 벌의 자모 영역에 있어야 합니다.
4. 모든 약어 키는 키와 결합 규칙으로 만들 수 있어야 하고, 현대 한글 음절이어서는 안 됩니다(일반 입력을 가리므로). 키가 중복되어도 안 됩니다.
5. 약어 설명서(xlsx)의 1,363개 항목을 "누르는 자모 → 결합 → 대응표 → 약어 키" 경로로 계산해, 약어 표와 하나하나 대조합니다.
6. 추가 약어는 적힌 키를 모든 순서로 눌러도 같은 음절이 되어야 합니다.
